# Два специалиста в одном личном проекте

Это тестовый формат 0.2.0 без установки навыков меню. Markdown (`.md`) — обычный текст инструкции, а не исполняемый агент. Команда запуска поручает ChatGPT прочитать выбранный файл и работать по нему.

## Один раз

1. Создайте облачный ChatGPT Project «ГРУППА РОСТА | <ИМЯ>». Локальную папку на компьютере для этого подключать не нужно.
2. В разделе Sources / «Источники» проекта добавьте **два отдельных распакованных файла**: «01 - ГР - НОРД.md» и «02 - ГР - РИТМ.md». Прикрепление только к установочному чату не означает добавление в источники проекта. ZIP сначала распакуйте.
3. В поле «Инструкции проекта» скопируйте текст между разделителями из «Настройки проекта.md».
4. Внутри этого проекта запустите Work с Sites по инструкции `docs/INSTALL_WORK.md` репозитория. Если личный Site уже существует, обновлять или повторно создавать его для теста специалистов не нужно. Выберите существующий личный плагин данных.

Общие источники и инструкции доступны чатам внутри проекта по документации OpenAI: https://learn.chatgpt.com/docs/projects . Фактический доступ к конкретным файлам и инструментам проверяется ниже; скачанная папка Work сама не становится источниками проекта.

## Первый чат — НОРД

Создайте новый чат **внутри проекта**, подключите свой личный плагин данных и отправьте:

```text
Запусти ГР - НОРД. Прочитай целиком «01 - ГР - НОРД.md» из источников проекта. Сначала прочитай сохраненную память через мой личный плагин. Назови этап и следующий шаг из фактического ответа. Ничего не записывай.
```

Можно назвать чат «01 | НОРД | МОЙ КУРС». Если файл недоступен, прикрепите его непосредственно к этому чату и повторите команду. Если инструмента нет, подключите свой плагин; инструкция файла не дает доступ к базе сама.

## Второй чат — РИТМ

Откройте другой новый чат **в этом же проекте**, подключите тот же плагин и отправьте:

```text
Запусти ГР - РИТМ. Прочитай целиком «02 - ГР - РИТМ.md» из источников проекта. Прочитай мои сохраненные курс, годовую цель, спринт и неделю. Назови фактический фокус недели; если исходных данных нет, скажи, чего не хватает. Ничего не записывай.
```

Можно назвать чат «02 | РИТМ | 12 НЕДЕЛЬ». Для обычной работы переходите к нему после согласования курса с НОРДом. Для технического теста можно запустить раньше: он должен увидеть пустые данные и не придумывать их.

## Что проверяем

- Оба новых чата прочитали именно свои полные файлы, а не придумали роль по имени.
- НОРД вызвал `gruppa_rosta_v1_get_nord_context`, РИТМ — `gruppa_rosta_v1_get_dashboard`.
- Получены фактические данные одного личного Site; отсутствие цели не заменено примером.
- После открытия того же проекта на телефоне повторный запуск в новом чате читает источники и ту же память. Этот шаг требует реальной проверки на устройстве владельца.
- В тесте без записи ревизия данных не изменилась. Для проверки сохранения отдельно согласуйте явно обозначенный технический итог; не заменяйте реальные цели примерами.

## Какие действия остаются ручными

В этом сценарии участник создает проект, добавляет два файла в его источники, вставляет общую инструкцию и открывает два чата. Автоматизация этих действий в текущем окружении не подтверждена. Work может подготовить и выдать файлы; это еще не добавление их в Project. Короткая команда выбирает специалиста, а не запускает установку навыка.

При смене чата личные итоги читаются из Site. При обновлении инструкций замените оба файла в источниках и текст настройки; не оставляйте одновременно две версии. Начните новый чат и повторите проверку чтения. Обновление инструкций не должно удалять или заменять личную базу.

Если Project недоступен в аккаунте, прикрепите первый файл к одному обычному чату, второй — к другому, и явно попросите применить соответствующую инструкцию. Доступность плагина в выбранном режиме проверяйте отдельно. Ручной вариант с локальным HTML описан в `docs/INSTALL_FREE.md` репозитория.
