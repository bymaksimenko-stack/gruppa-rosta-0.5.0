# Личная память и инструменты

Этот навык не содержит личного адреса сайта, идентификатора аккаунта, ключей или биографии. Он использует отдельно установленный личный плагин данных системы «Группа роста»; его видимое имя может быть «ГРУППА РОСТА | ЛИЧНАЯ СИСТЕМА» или «ГРУППА РОСТА | МОИ ДАННЫЕ». При нескольких подходящих подключениях уточни, какое принадлежит участнику.

## Прочитать контекст

`gruppa_rosta_v1_get_nord_context({})` возвращает `revision`, `beacon`, `passport`, `annualGoal`, `memory` и последнюю сверку курса. `memory` содержит:

- `summary` — краткие подтвержденные итоги;
- `stage` — текущий этап;
- `nextStep` — следующий шаг;
- `openQuestions` — нерешенные вопросы;
- `source` — откуда получен итог;
- `updatedAt` — время сохранения сервером.

Не подгружай все недельные отчеты без необходимости. Это первая ограниченная память продолжения НОРДа, а не полный архив переписок и не поиск по произвольной базе знаний.

## Записать память

`gruppa_rosta_v1_save_nord_memory` принимает:

```json
{
  "summary": "Краткий подтвержденный итог",
  "stage": "Текущий этап",
  "next_step": "Следующее действие в работе с НОРДом",
  "open_questions": ["Открытый вопрос"],
  "source": "Подтверждено участником в текущем разговоре",
  "expected_revision": 1,
  "confirm": true
}
```

Число `1` здесь — пример. Всегда подставляй ревизию фактического последнего чтения. Поле `confirm=true` не заменяет подтверждение пользователя: оно передается только при наличии его согласия на конкретное сохранение.

Запись заменяет текущую краткую память. Сохраняй еще актуальные факты предыдущего итога; исключай устаревшее только после уточнения. Сервер сохраняет предыдущую версию в истории. Полный экспорт сайта включает память.

## Структурированные результаты

- `gruppa_rosta_v1_save_beacon`: `title`, `desired_future`; необязательные `undesired_future`, `horizon`.
- `gruppa_rosta_v1_save_growth_passport`: `point_a`, `three_year_vision`; списки `strengths`, `constraints`, `values`. Передавай сохраненные актуальные списки целиком, чтобы не обнулить их частичным обновлением.
- `gruppa_rosta_v1_set_annual_goal`: `title`, `success_metric`; необязательные `target_date`, `progress`. Сохраняй актуальные срок и прогресс при изменении формулировки.
- `gruppa_rosta_v1_check_course`: `course_still_fits`, `note`; для содержательной сверки курса, а не для технических тестов.

Перед обновлением каждой сущности прочитай ее и передай полный актуальный набор полей: сервер заменяет сущность, а не выполняет частичное слияние. После структурированной записи ревизия меняется — перечитай ее перед записью памяти.

## Проверка из нового чата

Если участник просит проверить продолжение, прочитай память через инструмент и назови сохраненные этап и следующий шаг. Не угадывай их по предыдущим сообщениям. Технические маркеры храни только по явному поручению и обозначай как тестовые данные, не как факты о человеке.
