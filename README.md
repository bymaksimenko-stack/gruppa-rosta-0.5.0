# ГРУППА РОСТА — персональная self-deploy система

Один репозиторий разворачивает одну личную копию системы участника: приватный Site, персональное хранилище D1, MCP-плагин и два раздельных диалога в ChatGPT.

## Установка из GitHub

Репозиторий: https://github.com/bymaksimenko-stack/gruppa-rosta-personal-system

Исходники открыты по разрешению владельца: облачный Work может получить их по ссылке без доступа к компьютеру разработчика. Персональный Site, его хранилище и записи участника остаются приватными и в этот репозиторий не входят.

Основной тестовый формат 0.2.0: **один облачный проект и два файла специалистов**. Начните с [инструкции участника](project/Как%20начать.md) и [развертывания через Work](docs/INSTALL_WORK.md). Work получает исходники из GitHub, использует готовый код сайта и выдает комплект инструкций проекта. Импорт навыка через Plugin Creator для этого сценария не нужен.

| Порядок | Файл для источников проекта | Когда запускать |
|---|---|---|
| 01 | [ГР - НОРД](project/01%20-%20ГР%20-%20НОРД.md) | Сначала: курс, Паспорт роста, годовая цель |
| 02 | [ГР - РИТМ](project/02%20-%20ГР%20-%20РИТМ.md) | Затем: 12 недель, неделя, отчеты |

Текст для поля общих инструкций — [Настройки проекта](project/Настройки%20проекта.md). В новом чате участник пишет «Запусти ГР - НОРД» или «Запусти ГР - РИТМ». Чаты читают свои инструкции из источников проекта, а личные итоги — из того же приватного Site. Подготовка файлов не равна их добавлению в источники: этот шаг, настройка проекта и открытие чатов сейчас выполняются вручную.

В эталонной копии `.openai/hosting.json` нет `project_id`: каждая первая установка создает личный Site участника. После создания идентификатор сохраняется только в его личной рабочей копии. Личные данные хранятся в Site, не в этом репозитории.

Каталог `.agents/plugins/marketplace.json` позволяет проверить установку навыка из GitHub в поддерживаемом локальном клиенте. Это отдельный путь проверки, который не подтверждает установку в браузерном ChatGPT.

Дополнительный прежний путь: [пакет навыка НОРДа 0.1.0](https://github.com/bymaksimenko-stack/gruppa-rosta-personal-system/releases/tag/v0.1.0). Его локальная установка проверена, браузерная регистрация не выполнена. Он сохранен для совместимости локального клиента и не требуется для нового формата. Не считайте его установленным в аккаунт по наличию ZIP.

## Канонические имена

| Объект | Имя |
|---|---|
| Site | `ГРУППА РОСТА | ЛИЧНАЯ СИСТЕМА` |
| MCP-плагин | `ГРУППА РОСТА | МОИ ДАННЫЕ` |
| ChatGPT Project | `ГРУППА РОСТА | <ИМЯ>` |
| Чат 1 | `01 | НОРД | МОЙ КУРС` |
| Чат 2 | `02 | РИТМ | 12 НЕДЕЛЬ` |
| Навык НОРДа — утвержденное видимое название | `ГР - НОРД` |
| Навык РИТМа — утвержденное видимое название | `ГР - РИТМ` |

Все навыки, их инструкции, описания и подсказки запуска пишутся понятным русским языком. Утвержденный префикс видимых названий — `ГР - `. В описании обязательно указывается полное название «Группа роста» и назначение специалиста. Первый упакованный навык — `plugins/gr-nord`; локальная установка проверяется отдельно от сохранения в браузерном аккаунте.

## Что реализовано в MVP

- приватная авторизация через ChatGPT Sites;
- постоянное личное хранилище D1 без общего сервера и общей базы участников;
- светлая и темная темы, официальный логотип, Montserrat и палитра `#0056FF` / `#0F172A`;
- «Мой маяк», Паспорт роста, годовая цель, 12 недель, неделя, отчеты и колесо жизни;
- резервное копирование и восстановление JSON;
- история предыдущих ревизий перед каждой записью;
- MCP 2026-07-28 с версионированными инструментами `gruppa_rosta_v1_*`;
- инструкции для НОРДа и РИТМА;
- пакет навыка «ГР - НОРД» с методологией и чтением/сохранением памяти продолжения;
- схема данных v2 с переносом v1 без потери существующих полей;
- автономный HTML-вариант с `localStorage` для ручного сценария.

## Честные границы

- Sites создает связанный плагин после публикации MCP-Site, но установка/подключение может потребовать действие владельца в интерфейсе Plugins.
- Автоматическое создание ChatGPT Project, добавление Sources и открытие двух чатов не проверено и не заявляется. Участник выполняет эти шаги в интерфейсе по комплекту `project/`.
- Markdown-файлы специалистов не появляются в меню навыков. Само их добавление не запускает роль: нужна команда в выбранном чате.
- GitHub-ссылка дает агенту исходники и инструкции, но «один клик и все готово» подтверждается только отдельным тестом на чистом аккаунте участника.
- Локальный HTML не синхронизируется с облачным Site автоматически. Обмен идет через экспорт/импорт JSON.

## Структура

```text
project/                 два самостоятельных файла специалистов, настройки и порядок запуска
plugins/gr-nord/          дополнительный пакет навыка для прежнего локального сценария
app/                     интерфейс, API и MCP endpoint
db/                      схема личного хранилища
docs/                    архитектура, данные, установка и обновления
fallback/                ручной локальный HTML-вариант
lib/                     схема данных, миграция и сохранение
public/brand/            официальный логотип и Montserrat
public/images/           изображение для «Моего маяка»
```

## Локальная проверка разработчика

```bash
npm run db:generate
npm run check
npm run build
npm run dev
```

Локальная и опубликованная D1 — разные базы. Миграции в `drizzle/` неизменяемы после публикации.
