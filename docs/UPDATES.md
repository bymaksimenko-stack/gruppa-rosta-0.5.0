# Обновления без потери личных данных

## Разделение кода и данных

Git обновляет исходники приложения. D1 хранит личные записи отдельно от Git. Новый deploy не должен удалять таблицы, текущие строки или загружать демонстрационные данные поверх пользовательских.

## Правила миграций

1. Изменить `db/schema.ts` и схему состояния в `lib/growth-state.ts`.
2. Добавить мигратор из предыдущей `schemaVersion` в новую.
3. Запустить `npm run db:generate`.
4. Проверить сгенерированный SQL и metadata.
5. Не редактировать уже опубликованные SQL, snapshot и journal.
6. Снять JSON-копию тестовой записи.
7. Проверить обновление старой записи, экспорт и восстановление.
8. Только после этого публиковать новую Site version.

## Обновление личной копии

1. Участник скачивает JSON-копию.
2. Work открывает его личный репозиторий и подтягивает изменения из эталонного GitHub.
3. Агент показывает список изменений и миграций.
4. Выполняет сборку и тесты.
5. Публикует новую приватную версию того же Site — `project_id` не меняется.
6. Проверяет чтение старых данных через дашборд и MCP.
7. При ошибке не создает новый Site и не перезаписывает базу; исправляет миграцию новой версией.
