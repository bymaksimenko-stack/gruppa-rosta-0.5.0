# Развертывание через облачный Work: проект и два специалиста

Основной тестовый формат 0.2.0 использует Markdown-инструкции в источниках ChatGPT Project. Установку глобального навыка не требует. Файлы не являются исполняемыми агентами и не появляются в меню навыков.

## Сначала участник создает проект

Создайте облачный ChatGPT Project «ГРУППА РОСТА | <ИМЯ>», затем откройте в нем Work и выберите Sites. Если личный Site уже создан, передайте его ссылку и явно укажите, что нужно использовать существующую копию. Не создавайте заново Site ради добавления файлов специалистов.

## Сообщение для Work

```text
Разверни мою персональную систему «ГРУППА РОСТА» из https://github.com/bymaksimenko-stack/gruppa-rosta-personal-system. Используй формат project/ с двумя файлами специалистов, без обязательного импорта навыков.

Получи репозиторий из GitHub в текущую облачную рабочую среду. Не используй пути с компьютера разработчика. Назови фактический источник и Git commit. Полностью прочитай AGENTS.md, README.md, docs/DECISIONS.md и docs/ARCHITECTURE.md; перед работой с данными прочитай docs/DATA_AND_PRIVACY.md и docs/UPDATES.md.

Используй готовый код сайта. У меня должна быть одна личная копия: приватный Site, личное D1-хранилище и личный MCP-плагин. Если мой Site уже существует, используй его. Проверь .openai/hosting.json: при своем project_id обновляй этот Site; при отсутствии создай один Site «ГРУППА РОСТА | ЛИЧНАЯ СИСТЕМА», сохрани его id только в моей личной рабочей копии. При неизвестной принадлежности существующего id сначала уточни ее. Не обновляй чужой Site и не переноси чужие данные, токены или привязки. Каноническое имя плагина данных — «ГРУППА РОСТА | МОИ ДАННЫЕ»; если Sites назначает другое имя, сообщи фактическое.

Установи зависимости по lockfile, выполни npm run check:template для чистого шаблона до привязки личного Site, npm run check и npm run build. Не меняй опубликованные миграции. Опубликуй приватную версию поддерживаемым способом Sites; проверь MCP server/discover и tools/list. Не создавай дополнительный MCP-плагин поверх уже связанного с Site.

Выполни npm run package:project и выдай пользователю отдельными скачиваемыми вложениями точные файлы из project/: «01 - ГР - НОРД.md», «02 - ГР - РИТМ.md», «Настройки проекта.md», «Как начать.md», а также общий ZIP. Если среда не умеет выдавать вложения, укажи это и дай прямые ссылки на эти файлы в GitHub. Не выдавай внутренний путь рабочей среды за доступный файл.

Объясни ручные действия: два файла специалистов добавить в Sources проекта; текст между разделителями из «Настройки проекта.md» вставить в инструкции проекта; открыть первый чат и написать «Запусти ГР - НОРД», второй — «Запусти ГР - РИТМ». Оба чата используют мой личный плагин. Не утверждай, что скачанная папка Work автоматически добавлена в Sources или что чаты созданы, если ты этого не выполнил.

Если личный плагин доступен, проверь чтение через gruppa_rosta_v1_get_nord_context и gruppa_rosta_v1_get_dashboard без записи. Не заменяй мои данные тестовыми. Проверь, что ревизия после чтения не изменилась. В конце выдай URL Site, фактическое имя плагина, четыре файла, ZIP и отчет: что реально выполнено, что участник делает вручную и что еще не проверено. Мобильное продолжение и два новых чата в Project считай проверенными только после реального теста.
```

## Затем участник добавляет файлы и открывает чаты

Пошагово — [Как начать](../project/Как%20начать.md). Два файла добавляются в источники один раз, а роль выбирается короткой командой в новом чате. Контекст каждого специалиста восстанавливается из личного Site, не из предположений о содержимом соседнего чата.

## Дополнительный локальный вариант

Прежний пакет `plugins/gr-nord` и каталог `.agents/plugins/marketplace.json` оставлены для совместимости проверенного локального клиента. Это не установка в браузерный аккаунт и не обязательная часть текущего сценария. Подробности предыдущих проверок — `docs/GITHUB_TEST.md` и `docs/NORD_TEST.md`.
