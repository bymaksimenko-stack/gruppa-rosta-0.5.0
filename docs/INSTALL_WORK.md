# Установка из GitHub через облачный Work

Точка входа агента — [INSTALL.md](../INSTALL.md), готовая команда участнику — [START_TEST.md](../START_TEST.md).

## Действия участника

1. Создать облачный проект «ГРУППА РОСТА» и открыть в нем Work с Sites.
2. Отправить команду распаковки.
3. После выдачи готовых файлов открыть «Файлы проекта» и выбрать «01 - ГР - НОРД - Курс и годовая цель.md» для нового Work.
4. После работы над курсом выбрать «02 - ГР - РИТМ - 12 недель и планы.md» для отдельного Work.

Специалисты используют личный плагин одного Site и восстанавливают сохраненные итоги. Подключение этого плагина в конкретном новом Work проверяется фактическим чтением. Если интерфейс требует подтверждения подключения, его выполняет владелец.

## Действия установщика

Получить свежие исходники, применить готовый код сайта, сохранить личную привязку, выполнить проверки и приватную публикацию. Выдать два полных файла специалистов штатным механизмом файлов Work, дополнительно — «Как начать.md» и ZIP.

Для указанного пользователем пути не требовать предварительной ручной загрузки в общие Sources, распаковки ZIP или заполнения общих инструкций проекта. Выдача файлов Work, управление Sources и создание чатов через API — разные операции. Установщик не объявляет, что сам создал два чата: участник начинает Work с выбранным файлом.

## Проверка

Прочитать выбранный файл целиком в новом Work, выбрать правильный личный плагин, получить фактическую память. Наличие файла в разделе и поведение интерфейса не объявлять проверенными только по сохранению файла на диск контейнера. Различать результат инструментальных проверок и сообщение пользователя о его интерфейсе.

## Дополнительный прежний путь

Нативный пакет plugins/gr-nord сохранен для совместимости локального клиента. Он не является требованием запуска из файла Work и не подтверждает наличие глобального навыка в браузерном меню.
