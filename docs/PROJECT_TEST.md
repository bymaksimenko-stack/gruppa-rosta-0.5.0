# Историческая проверка формата 0.2.0

Текущий путь 0.3.0 описан в docs/WORK_FILE_LAUNCH.md: запуск через выданные файлы Work. Требование общих Sources и настройки ниже относится к прежнему тестовому варианту и для нового пути не применяется.

Дата подготовки: 30 октября 2026. Версия инструкций: 0.2.0.

## Границы проверки

Проверка упаковки и запуска по файлу в облачном Work отделяется от загрузки Sources в реальный ChatGPT Project и продолжения с телефона. Подготовленные файлы сами не устанавливают навык и не создают проект.

- `npm run package:project` — успешно. Четыре файла совпадают с исходниками; проверены целостность ZIP, русские имена с флагом UTF-8, существование упомянутых MCP-инструментов в контракте сайта и отсутствие обязательных внешних справок у специалистов.
- SHA256 ZIP: `1dc758a62a1fae89f0a938026ff04198cf62ab5d9569ffcf80be71d91ec2af72`.
- `npm run check:template` — успешно, 154 файла, без личных привязок Site и токенов.
- `npm run check` и `npm run build` — успешно.
- В ранее созданном отдельном облачном Work выполнен прогон commit `4522403e6a3934913d0c4c157203a229f3ee8d22`, полученного из GitHub. Прочитаны канонические документы и все четыре файла `project/`.
- В облаке успешно выполнены `check:template` и `package:project`; архив и отдельные файлы побайтно совпали с commit, SHA256 совпал с указанным выше.
- В первом диагностическом сценарии применена полная инструкция НОРДа и фактически вызван `get_nord_context`: прочитаны этап и следующий шаг; техническая запись не принята за биографию.
- Во втором диагностическом сценарии применена полная инструкция РИТМа и фактически вызван `get_dashboard`: выявлена нехватка исходных данных для содержательного планирования, без выдумывания цели.
- Повторные чтения в облаке подтвердили неизменную ревизию и идентичное состояние. Записи и изменения Site не выполнялись.
- Отдельная проверка из текущего клиента подтвердила совпадение общих полей двух инструментов и неизменность ревизии.
- [ZIP версии 0.2.0](https://github.com/bymaksimenko-stack/gruppa-rosta-0.5.0/releases/download/v0.2.0/gruppa-rosta-project-0.2.0.zip) скачан без авторизации; SHA256 совпал с локально проверенным архивом.

Оба диагностических сценария в облаке выполнены последовательно в одном Work. Они подтверждают доступность файлов, упаковку и стартовое чтение данных по инструкциям. Это не тест двух отдельных чатов с общими Project Sources. В облачной среде не было инструментов управления Projects/Sources; проект и новые чаты не создавались.

## Обязательный тест владельца в проекте

1. Создать облачный Project; добавить два распакованных файла в Sources и скопировать настройки проекта.
2. Открыть новый чат НОРДа; проверить полное чтение его файла и вызов get_nord_context.
3. Открыть другой новый чат РИТМа; проверить полное чтение его файла и вызов get_dashboard. Отсутствующая цель должна остаться отсутствующей.
4. Открыть этот проект на телефоне; повторить запуск в новом чате с тем же личным плагином.
5. Сравнить данные с Site. При тесте только чтения ревизия не должна измениться.

Пока эти шаги не выполнены в интерфейсе владельца, полный сценарий Project → два отдельных чата → телефон не считается проверенным.
