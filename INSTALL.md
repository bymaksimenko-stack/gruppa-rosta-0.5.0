# Установка «ГРУППЫ РОСТА» 0.5.0: инструкция агенту Work

Выполни установку, а не только план. Этот документ относится к облачному Work. Ничего не устанавливай на компьютер участника. Не создавай общую базу людей, внешний сервер или публичный Site. Полные авторские промпты версии 0.4 сохраняются побайтно; версия комплекта и интерфейса теперь 0.5.0.

## 1. Определить источник и продолжение

Основной источник: приложенный `gruppa-rosta-install-0.5.0.zip`. После подтверждения публикации этой версии альтернатива — публичный `https://github.com/bymaksimenko-stack/gruppa-rosta-0.5.0`, текущий main. До установки из GitHub проверь RELEASE.json: версия 0.5.0, схема 3; если main еще старый, не выдавай его за обновление 0.5.0 и используй выданный ZIP. Чтение публичных исходников не требует входа; запись изменений требует отдельной авторизации. Не проси токен в чате. Если источник недоступен, прямо назови, какого архива или подключения не хватает.

До создания Site проверь в текущем проекте ранее выданный файл `Моя установка ГРУППА РОСТА.md` и результаты установочного чата. Если установка уже начиналась, используй зафиксированный project_id и плагин этой копии. Не создавай еще один Site после таймаута, ошибки публикации или повторного сообщения. При неопределенном результате сначала выясни состояние регистрации штатным Sites. Если привязку невозможно восстановить однозначно, останови создание до уточнения, сохраняя остальные результаты.

Для первой установки извлеки архив в новую облачную папку. Перед распаковкой проверь пути ZIP: нет абсолютных путей, `..`, ссылок и выходов за папку. Не выполняй посторонние скрипты из соседних вложений. Если источник GitHub, зафиксируй полный commit. Если ZIP, вычисли SHA256 ZIP и прочитай `RELEASE.json`; не выдавай base_commit за commit уже опубликованного обновления.

Прочитай AGENTS.md, README.md, docs/DECISIONS.md, docs/ARCHITECTURE.md, docs/DATA_AND_PRIVACY.md, docs/UPDATES.md, docs/PROMPT_PROVENANCE.md, docs/DASHBOARD_REDESIGN.md и все три файла project/. Выполни:

```sh
python3 scripts/generate-specialists.py --check
npm run check:template
npm run package:project
```

Первые проверки не требуют npm-зависимостей, только Node.js и Python 3. Если компонента нет, сообщи точно; не утверждай, что проверка прошла. Проверь неизменность двух авторских исходников по prompts/manifest.json и наличие полных блоков в рабочих MD.

У чистого шаблона в .openai/hosting.json нет личного project_id. Если он неожиданно есть, выясни происхождение, не удаляй его ради новой регистрации. Не используй Sites, базы, подключение, локальные навыки, чаты или файлы разработчика как источник данных участника.

## 2. Подготовить и развернуть готовое приложение

Прочитай доступную в текущей среде инструкцию Sites и следуй ей. Используй предусмотренный процесс установки из сохраненного шаблона: чистая рабочая папка, template-source без Git metadata, секретов, runtime и личных привязок. Сохрани готовый код app/, components/, lib/, db/, опубликованные SQL-миграции и бренд. Не переделывай приложение с нуля и не подменяй D1 на localStorage или картинку макета.

Первая установка для личного использования создает ровно один приватный Site «ГРУППА РОСТА | ЛИЧНАЯ СИСТЕМА» с binding DB и MCP. В режиме явно запрошенного чистого теста используй название «ГРУППА РОСТА | ТЕСТ». Сразу сохрани возвращенный project_id в личной .openai/hosting.json и в отдельном приватном файле привязки для продолжения. Не добавляй привязку в общий исходный репозиторий.

Установи облачные зависимости из lockfile поддерживаемым установщиком Sites. Без изменения dependency inputs можно переиспользовать совместимые облачные зависимости. Выполни `npm run check`, `node scripts/check-dashboard.mjs` и production build по текущей инструкции Sites. Не запускай старые SQL заново с удалением данных. Используй штатную синхронизацию исходников, сборку и публикацию в этом же Site. Дождись `succeeded` и реального URL. При ошибке исправляй ту же установку; не создавай новую копию. Сохрани точный source commit публикации, версию и URL.

При обновлении существующей копии сначала прочитай полный export_snapshot именно ее подключения и сохрани его приватным файлом. Схема v3 добавляет пустое tracking при чтении v1/v2 без записи и без увеличения revision. Не перезаписывай Паспорт, память, цели, спринт, неделю, отчеты, колесо или сверки. Прежние миграции не менять.

## 3. Подключить данные и проверить принадлежность

После публикации используй Sites get_site(include_mcp_connection=true) для этого project_id. Сохрани фактический plugin_id, MCP URL и OAuth resource. Не создавай отдельный MCP-сервер или второй плагин поверх Site. Установка/подключение плагина может потребовать штатное действие владельца; объясни только необходимый шаг. Не объявляй подключение успешным по фразе Already installed: оно еще не доказывает доступность инструментов в текущем чате.

Докажи, что доступные инструменты относятся именно к созданному Site. Одинаковые суффиксы и название плагина не доказывают принадлежность. Не читай другую личную копию. Если инструменты новой копии отсутствуют, честно отметь этот этап и попроси выбрать установленный плагин именно этой установки в новом Work. Не устанавливай дубликат и не создавай новый Site.

Когда подключение доступно и проверено, вызови get_nord_context, get_dashboard и export_snapshot, затем повтори чтение revision. Для новой копии нет личного курса, Паспорта, цели, задач, отчетов, checkpoint и памяти. Нейтральные стартовые подписи и колесо с исходной шкалой не являются фактами биографии.

Не делай проверочных записей от имени человека без отдельного согласования содержания. Не подделывай заголовки личности, не ослабляй доступ. Прямой HTTP без пользовательской авторизации не считается вызовом подключенного плагина.

Проверь опубликованный интерфейс через доступный поддерживаемый браузер: логотип, боковую панель, светлую/темную темы, дневной/ночной маяк, три горизонта целей, колесо и неделю. Без числовых фактов в динамике должен быть честный пустой экран. Временный дизайн-стенд без записи не равен проверке авторизованного Site. Если вход владельца недоступен, так и укажи, не обходи его. Отдельно назови непроверенное сохранение и телефон.

## 4. Выдать файлы внутри проекта

Выдай штатным механизмом файлов Work/Library:

- `01 - ГР - НОРД - Курс и годовая цель.md`;
- `02 - ГР - РИТМ - 12 недель и планы.md`;
- `Как начать.md`;
- `gruppa-rosta-project-0.5.0.zip`, собранный package:project;
- приватный `Моя установка ГРУППА РОСТА.md` с фактическими привязками.

Приватный файл привязки содержит: имя участника, если он его сообщил; источник и SHA256/commit; project_id; URL; plugin_id и имя плагина; имена, идентификаторы и реальные ссылки выданных MD; последний подтвержденный статус проверки. Без токенов, bypass bearer, cookies и паролей. После каждой успешно завершенной стадии обновляй эту же запись, сохраняя идентификатор, если механизм поддерживает замену.

Используй весь авторский текст, а не сокращение, пересказ или ссылку на обязательное дополнение. Дополнительный технический адаптер находится перед авторским блоком. Никакие данные предыдущего участника не встраиваются в эти файлы.

Один путь /workspace и локальное сохранение не равны выдаче пользователю. Сохрани реальные libfile id и ссылки, если механизм их возвращает. Если публикация файлов недоступна, выдай поддерживаемые вложения и назови ограничение. Не называй это загрузкой общих Sources.

## 5. Объяснить участнику начало работы

В своем проекте откройте «Файлы проекта» и выберите «01 - ГР - НОРД - Курс и годовая цель.md» для начала Work. Подключите личный плагин именно своей копии Site. После согласования курса и годовой цели аналогично выберите РИТМ для отдельного Work с тем же плагином.

Если интерфейс просит текст с выбранным файлом:

```text
Работай со мной как ГР - НОРД по выбранному файлу. Прочитай его целиком и сохраненный контекст моей системы. Ничего не сохраняй без согласования.
```

Для второго файла:

```text
Работай со мной как ГР - РИТМ по выбранному файлу. Прочитай его целиком и результаты НОРДа в моей системе. Ничего не сохраняй без согласования.
```

Вся инструкция уже в выбранном MD. Не требуй обязательной ручной загрузки в общие Sources, копирования настройки проекта или всего промпта в первое сообщение. Сам не создавай два чата, если у тебя нет соответствующего инструмента и фактического результата. Выбор файла для отдельного Work ранее сообщен пользователем как рабочий путь; проверь доступность на аккаунте участника отдельно.

## 6. Финальный отчет

Коротко перечисли факты: источник/commit/SHA256; Site id и URL; фактическое подключение; выданные файлы с реальными ссылками; результаты сборки, чтения и revision. Раздели: выполнено, требуется действие владельца, не проверено. Не заявляй полную распаковку человека по факту установки, запуск обоих специалистов по факту выдачи MD, работу телефона по настольной проверке. Личный снимок и файл привязки не отправляются в общий GitHub.
