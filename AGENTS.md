# AGENTS.md

## Основное правило

При создании нового проекта первым создаётся файл `AGENTS.md`.

## Проект

Этот репозиторий — персональная self-deploy система «ГРУППА РОСТА».

- Один участник — один личный репозиторий, персональный Site и личное хранилище.
- Не добавлять общий сервер, общую базу пользователей или общий доступ без отдельного решения.
- Не объявлять функции рабочими без воспроизводимой проверки.
- Обновления обязаны сохранять персональные данные и сопровождаться миграциями схемы.
- Личные данные по умолчанию остаются в приватном контуре участника.
- Канонические решения отделять от гипотез и экспериментальных возможностей платформы.

## Язык и названия навыков

- Все навыки (skills), их инструкции, описания, подсказки запуска и справочные материалы писать понятным русским языком.
- Утвержденные видимые названия навыков: `ГР - НОРД` и `ГР - РИТМ`. Сохранять написание, пробелы и обычный дефис точно.
- `ГР` — утвержденный общий префикс системы «Группа роста». Для новых навыков применять формат `ГР - <ИМЯ>`.
- В русском описании каждого навыка указывать полное название «Группа роста» и коротко объяснять назначение специалиста, чтобы навык можно было узнавать и искать по обоим обозначениям.
- Не заменять видимые названия английскими именами вроде `Nord` или техническими идентификаторами. Имена НОРД и РИТМ утверждены пользователем.
- Если формат платформы требует технического идентификатора на латинице, использовать его только как служебное поле. Он не заменяет русское видимое название и описание.
- При проверке установки убедиться, что участник видит утвержденные русские названия и описания в меню выбора; проверить поиск по «ГР», имени специалиста и словам «Группа роста».

## Порядок работы

Основной формат 0.3.0 — два полных файла в project/: «01 - ГР - НОРД - Курс и годовая цель.md» и «02 - ГР - РИТМ - 12 недель и планы.md». Установщик выдает их штатным механизмом файлов Work внутри облачного проекта. Участник выбирает нужный файл в «Файлах проекта» и начинает с ним Work. Для этого пути не требовать обязательной загрузки в общие Sources или копирования общей настройки. Не смешивать выдаваемые файлы Work, Sources, локальную папку и меню навыков. Имена специалистов не менять; назначение и номер добавляются к имени файла. Проверку файла и упаковки отделять от наблюдения пользовательского интерфейса.

1. Прочитать `README.md`, `docs/DECISIONS.md` и `docs/ARCHITECTURE.md`.
2. Перед изменением интерфейса сверить официальный бренд в `public/brand/`.
3. Перед изменением данных прочитать `docs/DATA_AND_PRIVACY.md` и `docs/UPDATES.md`.
4. Не менять или удалять опубликованные миграции. Добавлять новую миграцию.
5. Перед публикацией выполнить `npm run check`, `npm run build` и релевантные сквозные тесты.
6. Если `.openai/hosting.json` уже содержит `project_id`, обновлять этот Site и не создавать новый.
7. Не записывать личные формулировки через MCP без подтверждения участника.

## Чистая распаковка

Точка входа установочного агента — INSTALL.md; короткая команда участника — START_TEST.md. При явно выбранном чистом тесте использовать свежие исходники из GitHub без личных привязок. Существующие Sites не удалять. После регистрации сохранять id этого прогона и при продолжении обновлять именно его. Проверка нового Site через старый плагин с теми же именами инструментов не засчитывается.
